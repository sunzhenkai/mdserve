## Context

图表成功渲染后，`DiagramPreviewDialog` 负责 Mermaid 内联 SVG 与 Kroki Blob 图片两种预览模式。当前适屏值按 `window` 尺寸计算并被限制为最多 `1.5`，交互缩放又被固定在 `0.2–5`；因此内在尺寸很小的矢量图只能显示为小块。预览容器实际已占满屏幕，问题集中在尺寸测量和缩放边界，而非弹窗布局、渲染器或服务端。

约束：两种嵌入模式需要保持相同交互；SVG 可无损放大；前端目前没有自动化测试框架；本变更不应扩展到普通 Markdown 图片预览。

## Goals / Non-Goals

**Goals:**

- 让小尺寸 SVG 初次预览时按实际可用视口适屏显示。
- 让最大缩放相对于适屏基准计算，用户始终能从适屏状态继续有效放大。
- 在视口变化后维护正确的适屏基准和重置行为。
- 统一 Mermaid inline 与 Kroki img 模式的缩放语义。

**Non-Goals:**

- 不修改图表生成、Kroki API、缓存或下载流程。
- 不改变正文内嵌图表的尺寸策略。
- 不统一普通位图预览，也不引入完整前端 E2E 基础设施。

## Decisions

### 1. 基于实际预览视口计算无固定放大上限的适屏值

适屏计算使用 viewport 元素的 content box，扣除统一安全边距后，取 `min(availableWidth / intrinsicWidth, availableHeight / intrinsicHeight)`。只要尺寸有效，就使用该值，不再以 `1.5` 限制小 SVG 自动放大。这样“fit-to-screen”同时适用于缩小大图和放大小图。

备选方案是仅提高固定上限（如 `3` 或 `10`），但任何固定绝对值仍会对更小的 SVG 复现同一问题，故不采用。

### 2. 缩放范围相对于适屏值动态派生

将缩放边界集中为纯计算规则：最小值不得高于适屏值；最大值至少为适屏值的四倍，并保留不低于现有绝对 `5x` 的放大能力。按钮和滚轮必须使用同一 clamp 结果。该规则保证大图仍可缩放，且小图不会因绝对 `5x` 上限失去放大空间。

备选方案是移除最大值，但无限缩放容易导致数值溢出、内容丢失和交互失控，因此保留有界动态上限。

### 3. 使用稳定的图形内在尺寸

Kroki `<img>` 使用 `naturalWidth/naturalHeight`。Mermaid inline 模式优先读取有效的 SVG `width/height` 或 `viewBox`，必要时回退 `getBBox()`；不以已受 CSS 与 transform 影响的 bounding rect 作为首选内在尺寸。测得尺寸后为 inline SVG 建立稳定基准尺寸，再由外层 transform 控制缩放。

备选方案是继续依赖 `getBoundingClientRect()`，但其值可能已包含布局约束，容易把当前显示尺寸误当作图形内在尺寸。

### 4. 通过 ResizeObserver 维护适屏基准

监听实际 viewport 尺寸。首次测量时应用 fit；视口变化时重新计算并保存 fit 基准：若用户仍处于旧 fit 状态，则同步到新 fit 并居中；若用户已主动缩放，则保留其缩放和偏移，仅按新边界 clamp。点击重置始终使用最新 fit 并恢复居中。

备选方案是监听全局 `window.resize`，但它无法覆盖弹窗内部布局变化，且不是实际计算对象。

### 5. 本次仅修改图表预览

缩放数学可在图表目录内提取为小型 helper，供 `DiagramPreviewDialog` 的两种嵌入模式共享。`ImagePreviewDialog` 虽有重复常量，但位图自动放大会涉及清晰度策略，不在本次范围内。

## Risks / Trade-offs

- [极小 SVG 会被初始放大很多] → SVG 为矢量内容，适屏仍受安全边距约束；用户可立即缩小或重置。
- [错误的 SVG 元数据导致异常比例] → 仅接受有限且大于零的尺寸，按明确优先级回退；无有效尺寸时保持安全默认行为。
- [ResizeObserver 引发重复计算或跳动] → 仅在尺寸实际变化时更新，并区分“仍处于 fit”与“用户已缩放”。
- [动态上限使百分比显示较大] → 百分比继续表示相对 SVG 基准尺寸，保持现有语义；不额外引入新的 UI 状态。

## Migration Plan

1. 提取或集中适屏与动态边界计算。
2. 将 inline/img 两条测量路径接入统一规则，并增加 viewport resize 处理。
3. 通过前端构建和浏览器场景矩阵验证小图、大图、极端宽高比、按钮/滚轮、重置和窗口变化。
4. 该变更无数据或配置迁移，可随前端发布直接生效；回滚只需恢复预览组件的旧缩放逻辑。

## Open Questions

无阻塞问题。动态最大值采用“至少 `max(5, fit × 4)`”作为首版规则，实际实现验证若发现浏览器数值或交互问题，可在不削弱规格保证的前提下提高上限。
